# MAT — the message banks (all game text)

Reference for `apricorn-core::formats::msg`, established in Phase 1 by
scanning every bank in the retail US dump (`hg_usa.nds`) and
cross-checking against pret/pokeheartgold's `src/msgdata.c`
(`ReadMsgData_ExistingNarc_*`, `Decrypt1`/`Decrypt2`) and the MSGENC
flags in `files/msgdata/msg.mk`. **The retail image is the oracle**: every
invariant below is pinned with zero violations across all 829 banks and
enforced at parse time.

Text lives in one NARC: `a/0/2/7`, built from `files/msgdata/msg.narc`.
Each of its members is a **MAT** (message archive table) holding one
bank of numbered messages; the game reads them through
`NARC_msgdata_msg` ids (`NARC_msg_msg_0237_bin` is the species-name
bank, `…0750` the move names).

Census (all counts pinned by `crates/apricorn-core/tests/msg_hg.rs`,
which parses all 829 banks):

| What | Count |
|------|-------|
| Banks (`a/0/2/7` members) | 829 |
| Messages | 49,984 |
| Code units (incl. EOS) | 2,106,048 |
| Messages per bank | 1 (min) – 1,717 (bank 728) |
| Unique bank keys | 786, never zero |
| LF units (0xE000) | 32,376 — nothing else in 0xE001..0xEFFF |
| Ext control codes (0xFFFE) | 13,926 — sizes 0/1/2 only |
| TRNAME units (0xF100) | 738 — 728 in bank 729, 10 in bank 246 |

## Layout

A MAT is a bare table — no magic, no Nitro container (which is why the
parser has no `is_msg_bank` heuristic; the census scope is the one
archive the game reads messages from):

| Offset | Size | Field |
|--------|------|-------|
| +0x00 | 2 | count — number of messages |
| +0x02 | 2 | key — per-bank seed for the entry obfuscation |
| +0x04 | 8·count | entries: `{ u32 offset (bytes), u32 length (u16 units) }` |
| 4+8·count | | string data — `length` u16 code units per message |

`length` counts the message's trailing **EOS unit (0xFFFF)**; the length
in bytes is `2·length`. Retail messages tile the member exactly: message
0 starts right after the entry table, each message follows the previous,
and the last one ends at the member end — no gaps, no slack, no
zero-length messages, verified on all 829 banks.

Per-bank keys are pinned per file in pret's `files/msgdata/msg.mk`
(`msg_0000.bin: MSGENCFLAGS += -k 0xFEE8`, `msg_0237: -k 0x782C`, …).

## The two XOR obfuscations

Both layers are rolling-XOR schemes, matching `msgdata.c`:

**Decrypt1 — the entry table.** Entry `n`'s `offset` and `length` are
each XORed with the same 16-bit seed replicated into both halves:

```text
seed = (key · 765 · (n+1)) & 0xFFFF     // 765 = 0x2FD
seed | seed << 16                        // XOR mask for both u32 fields
```

**Decrypt2 — the string units.** Message `n`'s units each XOR with a
seed that advances after every unit:

```text
seed = ((n+1) · 596947) & 0xFFFF        // 596947 = 0x91BD3
unit ^= seed ; seed = (seed + 18749) & 0xFFFF
```

The constants (765 / 596947 / 18749) are shared across the generation's
tools — PokePlat's `export_msg.py` decrypts Diamond/Pearl text with the
same three.

## Code units

Decrypted, a message is an array of u16 **code units** for the
generation's character encoding (full decode against pret's
`charmap.txt` is Phase 4 work — this module stops at the raw units).
What appears in the 49,984 retail messages:

| Units | Meaning |
|-------|---------|
| 0xFFFF | EOS, ends every message (counted in `length`) |
| 0xFFFE | ext control code: followed by `code` (u16), `size` (u16), then `size` field units |
| 0xE000 | linefeed (`CHAR_LF`) — the only 0xE0xx unit used |
| 0xF100 | TRNAMECODE — starts a packed trainer-name reference (`TRNAME_MASK` 0x1FF on the follow-up units) |
| 0x0001.. | characters: kana in the low range, `0x12b`.. spell US lowercase (`0x12b` = 'a', `0x136` = 'l', `0x13f` = 'u') |

Retail ext control codes carry `code` 0x0100–0x0205 (string variables,
colors: 0x0101 ×3,531, 0x0103 ×2,158, 0xFF00 ×3,568, 0x0200 ×738, …) and
0x34xx str-var codes, all with `size` 0, 1, or 2. The single-unit codes
0xFF01–0xFF0D from `charcode.h` never appear in this ROM — everything
goes through the 0xFFFE mechanism.

## Named banks (spot checks)

- **bank 0** — key 0xFEE8 (pinned by msg.mk); 12 messages.
- **bank 237** — species names, 496 messages. Message 0 is a placeholder
  row of dashes (0x1BE); species 1 is "Bulbasaur"
  (`[0x12c 0x13f 0x136 0x12c 0x12b 0x13d 0x12b 0x13f 0x13c]`), 249
  "Lugia", 250 "Ho-Oh" (`h,o,-,o,h`), 251 "Celebi".
- **bank 750** — move names, 468 messages; message 0 is a single dash.
- **bank 728** — the largest bank, 1,717 messages.
- **bank 729** — trainer names, autogenerated from `trainers.json`: the
  first 728 messages are TRNAME-packed references (0xF100 + packed
  chunks, e.g. `[0xF100 0x7DDE 0x7FFE]`).

## The other message archive: `scr_msg.narc` is vestigial

`msgdata/scenario/scr_msg.narc` exists in NitroFS and its path string
sits in ARM9's NARC-path table, but **it is leftover Diamond/Pearl data**
and nothing in the decompiled HGSS reads it:

- pret has no NARC id for it (`filesystem_files_def.h` has no entry) and
  no code references it — it is shipped untouched in `filesystem.mk`.
- Its 16 members are **not MATs**: they are `{ u32 count, u32 offsets[] }`
  tables whose strings are NUL-terminated (0x0000) u16 units — no
  0xFFFF EOS, no keys, no MAT entry table.
- The content decodes as Japanese Diamond/Pearl scenario text (Jubilife
  City references) with unmapped-code placeholders under HGSS's charmap —
  Platinum's generation-4 charmap differs from the one these strings
  were written with.

`apicorn` does not parse it; the census above covers `a/0/2/7` only.

## Where the banks live

`apicorn-tools msg` summarizes a NARC's banks (one line each) and dumps
one bank's messages as raw code units:

```sh
apricorn-tools msg hg_usa.nds a/0/2/7        # 829 banks, one line each
apicorn-tools msg hg_usa.nds a/0/2/7 237     # every species name
```
